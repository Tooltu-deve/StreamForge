# ADR-0003: Using OIDC for Github Actions


- **Date:** 2026-07-15
- **Phase:** Phase 0


## Context
- Problem: Github Actions tasks used for running **'terraform apply'** need a method to be verified by AWS to be able to make changes to the infrastructure of that AWS account. 
- Constraint: The solution should minimize the risk of leaking access key as well as the outcome if key is exploited by threat actors 

## Options considered
1. **Option A** — Store AWS Access Key, Secret Key in Github environment variables
2. **Option B** — Use OIDC token 
3. **Option C** — Self-hosted runner with EC2 instance profile

## Decision
I chose **Option B** because OIDC offers more advantages compared to the other solutions, OIDC tokens are short-lived so that they are only used in run-time and will expire shortly after that. Moreover, there is no need to store key in Github environment variable, instead we only need to store the IAM role ARN from AWS, which is useless to threat actors if they somehow exploit it. Meanwhile, option A requires storing keys in Github variable which is earlier stated insecured, option C is good because it needs no key either, but it adds infra to run/patch/secure a runner.

## Consequences
- Positive: No long-lived secrets in Github, credentials auto-expire
- Trade-offs / risks: the sub condition, which is used for restricting the repo being able to assume the role, must be written carefully so that it allows and denies repos correctly.
- Follow-up work this entails: Tighten sub in the future (only main branch for apply, PR for plan)
